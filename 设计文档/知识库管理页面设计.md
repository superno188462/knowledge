# 知识库工作区与切片规则设计

> 方案已按本设计实现。当前工作区用行内操作代替右键菜单；文件通过编辑相对路径后保存来移动/重命名，目录仅允许删除空目录。目录批量重新嵌入为同步操作，暂不支持中途取消。

## 目标和范围

将现有知识库管理页改成面向文件管理的工作区，交互参考 VS Code：左侧资源树管理目录和文件，中间编辑/预览当前文件，右侧按选择对象查看与编辑切片规则。保留知识库状态、检索测试等能力，但不让它们挤占文件管理主流程。

本次覆盖：创建目录、上传 `.txt`/`.md`、新建文本文件、打开和编辑文件、保存草稿、用户显式点击后嵌入、删除文件、配置目录/文件切片规则、规则变更后重新嵌入受影响的文件、查看检索结果来源。移动/重命名作为树中的明确操作；若后端已有稳定文档 ID，移动和重命名更新同一文档资源与切片来源，不创建重复目录项。

原文由 Knowledge 后端保存，以便文件编辑和未来重切片。Gateway 只保存每个切片记录的文本、metadata 和向量；业务项目负责解析、切片及生命周期。过去仅保存了哈希/切片 ID 而未保存正文的旧条目，无法凭现有 Gateway API 还原原文，首次重切片前必须重新上传原文件。

## 用户流程

1. 用户进入知识库工作区，左侧展示当前 collection 的文件树；文件夹可展开，文件可打开。
2. 用户可通过工具栏、目录上下文菜单创建目录/文本文件，或将 `.txt`/`.md` 上传到当前目录。
3. 上传文件或保存编辑只写入 Knowledge 本地原文草稿，不调用 Gateway；用户点击“嵌入”或“保存并嵌入”后，后端才按有效切片规则生成切片并调用 Gateway。
4. 选中目录或文件后，右侧规则面板显示该层规则和继承来源。目录规则影响其后代中未被更深目录或文件覆盖的文档；文件规则只影响该文件。
5. 保存切片规则前展示受影响文件数量和当前有效规则；确认后，逐个重新切片、写入新的向量记录，全部成功后才删除旧向量记录。失败时保留旧版本可检索，并在文件状态中提供失败原因和重试入口。
6. 规则字段支持结构优先、固定长度和自定义分隔符三种策略。结构优先会对 Markdown 识别标题/段落/代码块，对纯文本识别段落；超长块按句子、字符兜底。父子层级是独立开关，只对子块建立向量，父块本地保存并在检索命中后返回上下文。规则修改只重新嵌入有效规则发生变化的文档。
7. 搜索测试放在工作区独立的“检索”抽屉/页签，命中条目展示来源相对路径。

## 信息架构与布局

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ 知识库名称 / collection 状态 / 刷新 / 上传 / 新建文件 / 新建目录 / 搜索 │
├───────────────┬──────────────────────────────┬──────────────────────────┤
│ 文件资源树     │ 当前文件                      │ 检查器                    │
│               │ 名称、路径、同步状态           │ 对象：文件或目录           │
│ ▾ 产品        │                              │ 切片规则                  │
│   ▾ 安装      │ Markdown/Text 编辑区           │ 继承自 / 覆盖状态          │
│     指南.md   │                              │ 结构优先 / 固定 / 分隔符   │
│   API.md      │                              │ 长度、重叠或分隔符         │
│ + 添加        │                              │ 保存并重新嵌入影响范围     │
├───────────────┴──────────────────────────────┴──────────────────────────┤
│ 底部状态栏：集合、模型、当前文件同步状态、切片数；检索抽屉可展开          │
└─────────────────────────────────────────────────────────────────────────┘
```

- 顶部工具栏呈现常用文件操作和 collection 状态；集合模型/切片上限等详情放入状态弹层，避免占用主工作区。
- 左侧文件树支持展开/收起、键盘 Tab/Enter 操作；文件通过行内删除按钮执行删除确认，目录和文件用不同图标及同步状态徽标。
- 中间内容区按对象显示：文件显示编辑器，目录显示子项和目录级规则摘要，未选择时显示空状态。
- 右侧检查器按当前选中对象切换；文件可“继承目录规则”或设置单文件覆盖，目录可配置规则并显示递归影响范围。
- 小屏幕下检查器与树改为可切换侧栏，编辑区优先保留宽度；页面主体可纵向滚动。

## 切片规则模型

规则是可选覆盖，按最近祖先继承：collection 默认值 → 根目录/上级目录 → 当前目录 → 文件。文件显式选择“继承”时不保存覆盖；目录显式设置规则后作用于其后代，后代可再次覆盖。

```json
{
  "strategy": "fixed",
  "chunk_size": 1000,
  "overlap": 120
}
```

或：

```json
{
  "strategy": "delimiter",
  "delimiter": "\\n## ",
  "chunk_size": 1000,
  "overlap": 0
}
```

默认规则与父子层级示例：

```json
{
  "strategy": "structure",
  "chunk_size": 1000,
  "overlap": 120,
  "hierarchy_enabled": true,
  "parent_chunk_size": 4000,
  "parent_heading_level": 2
}
```

- `strategy=structure`：Markdown 识别标题、段落、列表/代码块；纯文本识别段落。优先在这些结构边界切分，超长块再按句子和字符兜底。
- `strategy=fixed`：按字符数切分；尽量在换行/句末边界收束，最终单片不得超过 collection 的 Gateway `chunk_size` 上限。
- `strategy=delimiter`：按用户指定的字面分隔符切分；超长段落继续按固定长度切分，保证不超过 Gateway 上限。分隔符是否保留在前一片采用一致的“保留”策略，避免内容丢失。
- `hierarchy_enabled=true`：按 Markdown 标题层级（默认 `##`）或纯文本段落生成有长度上限的父块；父块只存在 Knowledge 本地，只有子块写入 Gateway 向量 collection。检索命中子块后，服务端返回对应的 `context_content` 父块文本。
- `overlap` 表示相邻切片字符重叠数，限制为小于 `chunk_size`；目录规则影响较多文件时，在保存确认中展示预计重嵌入文件数。
- Gateway collection 的最大文本长度仍是硬上限；本地规则不能突破它。非法正则/空分隔符等输入即时校验；分隔符作为普通文本处理，不执行任意正则。

## 重新嵌入与数据一致性

规则或正文变更时，使用内容哈希 + 有效规则哈希 + 切片序号生成新一代稳定 ID。新一代所有向量写入成功后再删除旧 ID，并切换本地活动映射；失败时删除未完成的新一代记录，保留旧活动向量与可检索状态，记录失败状态并允许重试。内容不变且有效规则不变时不重复嵌入。

目录规则保存之前计算后代文档的有效规则差异，只处理确实改变的文档；嵌入按 Gateway 批量上限分批执行。批处理状态可逐文件显示成功/失败，不把失败文档标成已更新。

## Metadata 与溯源

每条向量切片由当前项目单独生成 metadata。必须有 `source`，其值是 collection 根目录下规范化的相对路径，例如 `产品/安装/指南.md`，使用 `/` 分隔且不以 `/` 开头。另保留业务过滤与映射字段：

```json
{
  "app_id": "knowledge-platform",
  "record_type": "knowledge_chunk",
  "document_id": "<内部稳定 ID>",
  "source": "产品/安装/指南.md",
  "chunk_index": 0,
  "chunk_count": 3,
  "content_sha256": "<整篇正文哈希>",
  "chunk_sha256": "<当前切片哈希>",
  "metadata_schema_version": 1
}
```

自定义 metadata 仍允许添加，但不能覆盖 `source`、`document_id`、`chunk_index`、`app_id` 和 `record_type` 等受保护字段。检索结果展示 `source` 作为可点击的相对路径。

## 前后端契约草案

- `GET /api/knowledge-base/tree`：返回当前用户有权访问的目录树、文件摘要、同步状态和规则覆盖标记。
- `POST /api/knowledge-base/directories`：创建空目录 `{path}`。
- `PUT /api/knowledge-base/directories/rule`：保存目录规则 `{path, rule}`，返回受影响文档数及逐文件重嵌入状态。
- `GET /api/knowledge-base/documents/{document_id}`：读取文档正文、相对路径、metadata、覆盖规则、有效规则及同步状态。
- `POST /api/knowledge-base/documents`：新建/更新文本资源；支持 `{document_id?, path, content, metadata, chunking_rule?}`。省略文件级规则表示继承。
- `PUT /api/knowledge-base/documents/{document_id}/move`：移动/重命名文档，更新 `source` 并重新写入对应切片。
- `PUT /api/knowledge-base/documents/{document_id}/chunking-rule`：更新单文件规则或设为继承，并重新嵌入该文件。
- `POST /api/knowledge-base/documents/{document_id}/reindex`：使用当前有效规则重试重嵌入。
- `DELETE /api/knowledge-base/documents/{document_id}`、`DELETE /api/knowledge-base/directories?path=...`：删除时校验目录是否为空；递归删除需明确确认，并按文档清理其向量。
- `POST /api/knowledge-base/search`：检索返回的每个切片 metadata 均含 `source`；父子模式还返回本地加载的 `context_content` 和 `parent_id`。

所有请求由当前用户身份及 Gateway Key 服务端权限校验；不能从请求体接受任意 `owner_user_id`。错误返回机器可读 code 和可展示 message，不暴露 Gateway 凭据。

## 界面状态与可用性

- 初始加载、集合未配置、空目录、空文件、文件加载、未保存修改、保存中、嵌入成功、部分失败、规则继承、规则覆盖、重新嵌入确认、目录删除确认均有明确状态。
- 保存规则时禁用重复提交；切换文件遇到未保存编辑应提示保存/放弃/取消。
- 目录规则批量重新嵌入会逐文件显示成功、失败或需重新上传状态；当前请求完成前不能中途取消。
- 文件树和检查器可键盘操作，焦点态可见，图标不能是唯一状态提示；状态提供文字和颜色双重标识。
- 桌面布局适配窄视口，不依赖整个浏览器窗口固定高度而隐藏滚动条。

## 实施验收点

1. 用户能创建目录、上传/新建/编辑/移动/删除文件，并在刷新后从后端恢复文件树和正文。
2. 目录、子目录和文件规则有确定的覆盖优先级；修改规则只重嵌入有效规则变化的后代。
3. 结构优先、固定长度与自定义分隔符切片均受 Gateway 单片长度上限约束；父子模式的子块可关联到本地父块。
4. 规则/正文更新成功前旧向量仍可用；失败时旧版本不丢失并显示可重试错误。
5. 每个向量记录拥有独立 ID/metadata，`source` 始终是规范化相对路径；更新移动后来源同步改变。
6. 旧条目没有本地正文时，页面说明需重新上传，不能伪称已经重新嵌入。
