# 数据中台与共享向量数据约定

## 系统边界

- **knowledge 数据中台**管理知识文件虚拟目录、文档原文、切片、切片 metadata 和文档生命周期；切片完成后逐条调用 Agent Gateway 向量 API。
- **rtc 语音项目**只通过 Agent Gateway 检索知识切片，不提供知识库文档的上传、更新或删除入口。
- **其他业务项目**可把长期记忆等文本记录写入 Gateway 向量集合；记录生命周期由写入它的业务项目负责。
- **Gateway**是共享向量底座，负责 collection、Embedding、向量记录和相似度查询。项目本地 PostgreSQL 只保存本项目需要的账号、业务目录或会话状态，不存向量。

## Gateway 可见范围

Gateway 向量 API 按 Gateway 项目隔离，API Key 自动确定项目。若多个应用需要访问同一个 collection，应为它们创建**同一个 Gateway 项目下的不同 API Key**，并在服务端分别配置。只填写相同 collection 名称、但使用不同 Gateway 项目 Key，并不能共享数据。

当前 Gateway 提供 collection 列表、upsert、按 ID 删除和相似度查询，没有列举 collection 中全部向量记录的 API。因此数据中台能够对共享 collection 做 metadata 过滤后的相关性查询，但不能把其他项目的记录当作可分页浏览的完整目录。其他项目记录的更新/删除仍由对应业务项目负责。

同一 Gateway 项目下的 Key 具有项目级访问范围，而非 collection/metadata 级 ACL。共享项目适合服务端之间的受控访问；不要把 Gateway Key交给浏览器。数据中台的跨应用检索接口只允许管理员角色，普通账号被限制在知识切片范围内。

## 共享 collection 的 metadata

collection 的 Embedding 模型和维度固定；所有写入者必须遵循该设置。不同应用通过每条记录自己的扁平 metadata 分类：

| 字段 | 知识切片 | 其他业务/长期记忆 |
| --- | --- | --- |
| `app_id` | `knowledge-platform` | 稳定的业务应用标识，如 `rtc-voice` |
| `record_type` | `knowledge_chunk` | `long_term_memory` 等 |
| 身份字段 | `document_id`, `chunk_index`, `chunk_count` | `memory_id`, `external_user_id`, `memory_type` |
| 溯源字段 | `path`, `name`, `file_name`, `source_type` | `source`, `schema_version`, `confidence` |

知识切片由中台固定写入 `app_id=knowledge-platform` 和 `record_type=knowledge_chunk`。语音 Agent 的 RAG 查询必须同时过滤这两个字段，避免把用户长期记忆混入公共知识回答。未来的用户记忆检索必须同时过滤 `app_id=rtc-voice`、`record_type=long_term_memory` 和当前稳定用户 ID，不能只按语义相似度搜索。

`app_id` 和 `record_type` 是跨应用约定，不是 Gateway 当前的行级安全策略。各业务后端必须固定注入自己的过滤值，不能信任浏览器传入的 owner/user 过滤条件。数据中台管理者对其他应用记忆的检索应有明确权限和审计；不要向普通知识库用户开放。

## 用户账号与 ID

Knowledge 与语音业务使用 Identity Center 验证后的同一个 `user.id` 作为 canonical 用户标识；各业务项目仍将自己的文档、会话和权限保存在本项目数据库。Knowledge 新建的文档及向量切片使用 `owner_user_id` 隔离。不要用用户名或 email 代替稳定 ID。

Identity Center 当前使用 opaque HttpOnly Cookie，Knowledge 后端通过 BFF 转发并向 `/api/auth/me` 验证；这共享了账号与用户 ID，但不构成多个应用之间的 OIDC 单点登录。业务权限和资源授权仍由各应用维护。Gateway API Key、collection、数据库 URL 等部署配置不应作为用户中心的数据模型。

## 当前已实现与待接入

knowledge 管理端会给新写入的知识切片添加 `app_id` 和 `record_type`，默认检索限定在知识切片。管理员可以通过 Gateway 相似度查询读取共享 collection 中其他类型的相关记录。rtc 语音 Agent 只检索知识切片。

目前语音项目的长期记忆仍使用 Gateway Context 文本记忆接口；尚未将长期记忆 embedding 并写入向量 collection。后续接入时再增加独立的长期记忆向量写入/更新/删除适配器，并遵守上述 metadata 约定。Gateway 目前也不支持全量向量枚举，所以长期记忆目录仍应由业务侧保存 ID/版本关系，或由 Gateway 增加专用列表/过滤 API。
